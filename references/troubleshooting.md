# 排障手册

## 排查顺序

1. **有头复现**:`--headless 0` 跑一次,肉眼看到底是登录页、验证页还是正常列表。
2. **看日志**:脚本会打印「卡片选择器命中 / 抽取 N 条」。命中 0 或抽取 0 是改版信号。
3. **看 raw**:`raw/{site}__{kw}__{city}.json` 存了该次原始结果与 `meta.notes`,
   里面有「导航失败 / 命中登录墙 / 无卡片」的具体原因。
4. **单条验证**:先用 1 个关键词、1 页跑通,再放大。

## 常见情况

### 抽取 0 条,但页面肉眼正常
状态树字段名变了。打开 DevTools Console 执行 `Object.keys(window.__INITIAL_STATE__)`,
对照 `references/platforms.md` 的字段路径,更新 `extract_zhaopin_state` 里的 JS。

### 卡片选择器命中 0
站点改版。DevTools 里右键岗位卡片 → 复制 selector,把新选择器补到
`SITES["zhaopin"]["card_candidates"]` 列表**最前面**(脚本按顺序探测,取首个命中 ≥3 的)。

### 命中登录墙 / 反复跳登录页
- 智联偶尔会弹登录,稍后重试通常可恢复;频繁出现说明该 IP 被限,降低频率。
- BOSS直聘必须登录:`--login --site zhipin` 扫码。登录态存在 `profile/`,
  有效期取决于站点,过期需重扫。

### 出现「滑动验证页面」
触发了 captcha,通常是频率过高。**停止抓取,等 10–30 分钟**再试,
并降低 `--pages`。不要试图绕过验证码。

### 导航超时
智联搜索页首帧较大(约 1.8MB),慢网络下 30–45 秒是正常的。
脚本超时设 45 秒;若仍失败,检查网络与代理,或稍后重试。

### 薪资全是「未标注」
说明只跑到了 DOM 解析(状态树为空)。确认:
- 是否滚动了页面(滚动才触发状态树补齐)
- `meta.extract_mode` 是否为 `initial_state`
- 若为 `dom`,参考上面「抽取 0 条」排查状态树

### 技能标签里混入行业名(如「软件/IT服务」)
`_filter_skills` 的黑名单需要补充。把新发现的非技能词加进 `NON_SKILL_RE`。
判断标准:这个词不会出现在简历技能栏里。

### 报告里分档数字对不上总数
分档统计在 `analyze()` 里,`dist` 的 key 必须与 `verdict()` 返回值完全一致。
改判断文案时注意同步。

## 红线

- **不要**为了提高成功率去加并发、缩短 sleep,或使用验证码打码服务。
- **不要**在抓取失败时用旧数据或记忆里的数据冒充本次结果。
- **不要**把抓取到的候选人/HR 联系方式用于主动联系。
